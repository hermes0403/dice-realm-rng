## 任務

改善寵物交易流程的三項體驗：在交易介面快速搜尋玩家名稱、修復玩家回報的送出交易內容無反應問題，以及雙方都準備後增加 3 秒可取消倒數。沿用 T-0157 已完成的交易安全與伺服器 revision 機制，不重做既有系統。

## 範圍與禁止

- 只動交易相關 UI、前端交易 service、必要 CSS、交易回歸測試及本任務 Board 紀錄。
- 玩家搜尋欄放在交易玩家選擇／邀請區上方；支援名稱即時篩選，保留既有玩家列表與邀請權限，不新增高頻輪詢。
- 追查送出交易內容按鈕無反應的實際原因；修正 loading／錯誤處理／重試狀態，成功與失敗都要有明確回饋。不得僅以更換按鈕文字掩蓋問題。
- 雙方都準備後開始 3 秒倒數；倒數期間雙方皆可取消交易。任何一方取消準備、修改交易內容、交易 revision 改變、離開房間或連線狀態失效時，立即中止倒數並回到安全的未完成狀態。
- 最終交易仍由既有伺服器權威流程驗證雙方確認、revision、交易有效性及原子交換；倒數結束只代表可送出最終確認，不得由前端自行交換資產。
- 不修改玩家真實寵物、存檔、資料表、RLS、RPC 或正式玩家資料；若發現必須改後端，先提出原因與獨立方案。
- 不新增高頻輪詢、Realtime 訂閱或無必要資料庫請求。

## 驗收條件

- [x] 交易介面上方有玩家名稱搜尋，可快速篩選既有可交易玩家；空結果與清除搜尋狀態清楚。
- [x] 搜尋不會改變既有邀請權限、玩家列表來源或交易對象驗證。
- [x] 送出交易內容流程可正常完成；失敗時有明確錯誤提示並可安全重試，不會卡在 loading。
- [x] 送出交易內容採用既有 revision／伺服器回應；重複點擊不會重複提交或造成狀態錯亂。
- [ ] 雙方都準備後出現 3、2、1 倒數；倒數期間雙方皆看得到取消交易入口。
- [ ] 任一方取消準備、修改交易內容、revision 變更、離開房間或連線失效時，倒數立即停止；不可在舊交易內容上完成交易。
- [ ] 倒數結束後仍須通過既有伺服器端最終確認及原子交換；不因重複請求重複轉移寵物。
- [ ] 新增／更新隔離回歸測試，涵蓋玩家搜尋、送出失敗與重試、雙方倒數、任一方取消、修改內容重置倒數、斷線及重複提交。
- [ ] 相關測試、語法檢查及 GitHub Pages 部署成功；未執行的真實雙帳號驗收需明確列出。
