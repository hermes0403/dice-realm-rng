## 任務

修復跨裝置／分頁的舊雲端存檔覆蓋問題，並對玩家 `𝕤𝕝𝕖𝕖𝕡(afk）` 的異常回退執行一次性補償。

## 範圍與禁止

- 只動：雲端存檔同步版本檢查、必要的 Supabase RPC／相容性防護、此玩家的補償紀錄及資料、必要測試與本任務紀錄。
- 不要動：其他玩家資產、遊戲抽取機率表、玩家背包容量上限、其他分支或 main。
- 補償依已確認差額增加 91,386 抽與 384,819,467$；骰子結果使用目前遊戲一般擲骰權重作可重現的近似模擬，明確記錄種子與假設。所有補償骰子直接入袋，不套用自動出售／自動材料設定。
- 補償必須使用唯一 grant key／交易紀錄，確保重跑不會重複發放。
- 存檔寫入須以伺服器端原子版本檢查拒絕舊版本；衝突時載入雲端最新資料，不得自動重送舊快照。

## 驗收條件

- [ ] 同一帳號兩個分頁以相同版本寫入時，只允許第一筆成功，第二筆收到 conflict 並重新載入雲端存檔。
- [ ] 舊版直接寫入若令擲骰總數下降，資料庫拒絕該次更新。
- [ ] 同步成功時 game_saves 與 player_profiles 在同一資料庫交易內更新。
- [ ] 補償紀錄唯一；重複執行不會重複增加骰子、擲骰數或金錢。
- [ ] 補償後驗證擲骰數、金錢、骰子背包與補償紀錄一致。
- [ ] `git diff --check` exit 0；列明未執行測試及部署限制。
