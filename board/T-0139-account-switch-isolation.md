## 任務

修復玩家使用各自的玩家名稱／帳號與密碼登入時，切換帳號後會看到上一個帳號完整遊戲資料的問題。每個帳號必須只載入自己的雲端存檔；A 帳號的資料、快取、延遲回應及背景寫入都不得進入 B 帳號。

## 範圍與規則

- 檢查並修正 Auth 登入、登出、切換帳號、雲端存檔載入、保存及初始化流程。
- 切換帳號時先封鎖保存與權威操作，隔離舊帳號的 pending timer／請求／初始化世代，再初始化新帳號。
- 雲端資料必須以 Supabase Auth user ID 為唯一隔離依據；不得用玩家名稱作為資料隔離鍵。
- 禁止將未確認身分的共用 localStorage key、上一位玩家的記憶體狀態或離線存檔合併到新帳號。
- 舊帳號的非同步回應即使晚到，也不得修改目前畫面、目前記憶體狀態或新帳號的快取／雲端資料。
- 新帳號完成自己的雲端 bootstrap 前，遊戲資產與權威操作必須鎖定；載入失敗時顯示錯誤，不得顯示其他帳號資料。
- 保留所有現有玩家的雲端存檔，不得為了修正隔離而清空、覆蓋、重建或自動搬移任何帳號資料。
- 不在前端儲存密碼、access token 或 service-role key；沿用既有安全登入服務。
- 優先採用低流量流程，不新增高頻輪詢或 Realtime。

## 驗收條件

- [ ] 玩家可分別輸入自己的帳號／玩家名稱與密碼登入。
- [ ] A 登入後只看到 A 的名稱、金錢、骰子、寵物、背包、成就及其他遊戲資料。
- [ ] A 登出後登入 B，B 只看到 B 自己的資料；不得短暫閃現 A 的任何內容。
- [ ] B 登出後重新登入 A，A 原有資料完整保留。
- [ ] A→B→A 快速切換、重複登入、登出期間延遲回應、刷新頁面及多分頁情境均不會跨帳號污染。
- [x] 舊帳號的延遲保存不得覆蓋新帳號；新帳號載入失敗不得使用共用本機資料補值。
- [ ] 以兩個隔離測試帳號執行端到端回歸，逐項比對兩邊資料。
- [x] 既有登入、註冊、重新登入、存檔同步及登出流程通過回歸測試。
- [x] git diff --check、JavaScript 語法檢查及相關測試通過；測試命令與 exit code 記錄於完工回報。
