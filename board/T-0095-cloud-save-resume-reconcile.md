## 任務

處理玩家切換 App、瀏覽器休眠、分頁從背景恢復或網路重新連線後，舊頁面仍持有舊雲端版本的風險。頁面恢復時重新讀取最新雲端存檔，使用 T-0094 的共同基準三方合併保留本機未同步差異，再以最新雲端版本繼續同步。

## 範圍與禁止

- 只修改雲端存檔生命週期、必要的回歸測試、CI 測試清單、前端版本與 PWA 快取版本、Board。
- 不修改骰子機率、遊戲經濟、背包規則、遊戲玩法或 Supabase schema。
- 不增加每次擲骰的 Supabase 請求；只在頁面恢復、重新顯示或網路恢復時重新核對。
- 不以本機時間戳或整份本機快照直接覆蓋雲端。
- 不直接覆寫 main；先由任務分支與 PR 驗收。
- 遊戲版本遞增 0.01，PWA cache 同步更新。

## 驗收條件

- [ ] 分頁從背景恢復可重新讀取雲端最新版本。
- [ ] bfcache pageshow 與 visibilitychange 同時觸發時，不會重複發送載入。
- [ ] 恢復時若本機仍有未同步進度，必須透過共同基準三方合併保留可安全合併的差異。
- [ ] 恢復期間若原有同步尚未結束，待同步完成後仍會執行雲端核對。
- [ ] 網路重新連線時重新核對，離線期間不嘗試覆蓋雲端。
- [ ] 新增自動化測試，確認本機與遠端各自新增骰子後，恢復頁面仍保留兩邊的骰子、rollCounts、首次發現與累積擲骰。
- [ ] JavaScript 語法、差異檢查、重點存檔測試通過；GitHub Pages 部署成功。
