## 任務

在新雲端權威流程完成切換並穩定後，逐項核對舊 game_saves、profile 與 grant 資料，完成必要資料收斂，並安全退場不再使用的舊 RPC、overload、直接寫入權限及 RLS policies。

## 範圍與禁止

- 只動：
  - legacy 資料來源盤點、逐帳號核對工具／報告、保留原始證據、已核准資料轉換、舊前端呼叫路徑確認、撤權／退場 SQL 與回復計畫。
- 不要動：
  - 未完成 P0～P5 時的正式資料轉換、未核對資料的自動認列、未經 Owner／正式授權管理者執行的正式環境變更。
  - 正式環境 DDL／DML、migration、RLS／grants 變更與部署只能由具備權限的 Owner／管理者執行；COS 只能準備 SQL、步驟及驗證方式。
  - 不得提前撤銷仍被 GitHub Pages 線上版本使用的舊權限或 RPC。
- 實作前依 Board 規則取得本任務專用 branch／worktree 的人類授權；不得自行建立。

## 驗收條件

- [ ] P0～P5 全部完成並已在目標環境部署、驗收後，才開始執行舊資料收斂及退場。
- [ ] 每一類 legacy 資料都有來源、筆數／範圍、可信度、處理決策及可追溯結果；未核對資料不自動成為權威資產。
- [ ] 確認線上前端及所有仍受支援版本不再呼叫舊寫入路徑，並具備切換／回復方案。
- [ ] 撤權 SQL 僅移除已確認不再使用的權限、policy、RPC／overload；保留仍需相容的讀取路徑。
- [ ] 正式操作由具權限 Owner／管理者執行；保存執行結果與唯讀驗證證據。
- [ ] 補上未授權、跨帳號、重複請求、併發及 rollback 測試；依任務範圍選用適用案例。
- [ ] git diff --check exit 0；相關測試指令與 exit code 記錄於任務紀錄。
