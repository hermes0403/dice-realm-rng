## 任務

將骰界 RNG 的登入方式擴充為「玩家名稱／Gmail + 原密碼」雙入口，並新增不需要 Gmail 的玩家名稱註冊。保留既有 Supabase Auth 帳號 UID 與全部遊戲資料；管理員可查看登入名稱、UID、帳號狀態並重設密碼，但永遠不能查看原密碼。

## 範圍與禁止

- 只修改登入／註冊／管理員帳號管理所需的前端、Auth service、Edge Function、SQL migration、文件及專項測試。
- 既有帳號：已指派登入名稱者，可用登入名稱或原 Gmail 搭配原密碼登入同一 UID；未指派登入名稱者，繼續使用原 Gmail 與原密碼。
- 依棒子已提供的三組對照，將登入名稱映射至已存在的精確 Auth UID；必須以既有玩家資料與 Auth UID 交叉確認，不得按顯示名稱猜測、不得建立替代帳號。
- 新玩家可直接註冊：玩家名稱、密碼、再次輸入密碼；不要求 Gmail、不寄驗證信、不寄通知信、不要求管理員核准。
- 玩家名稱需大小寫不敏感且唯一；登入名稱只作登入識別，不覆蓋既有玩家的遊戲顯示名稱。新玩家可用登入名稱作為初始遊戲名稱。
- 新帳號使用 Supabase Auth 管理密碼及安全雜湊；禁止在資料表、日誌、前端或管理員介面保存／顯示明文密碼。
- 管理員帳號清單需顯示登入名稱、UID、帳號狀態；未設定登入名稱者顯示未設定。管理員可替玩家設定新密碼，但不得查看原密碼；重設動作需有管理員權限驗證及稽核紀錄。
- Gmail 登入保留原有行為；玩家名稱登入不得回傳或洩漏綁定的 Gmail。錯誤訊息需避免透露帳號是否存在。
- 新增登入名稱映射資料表時啟用 RLS，僅允許受信任的 Edge Function／service role 存取；service-role key 絕不可進入前端。
- 對註冊、登入與密碼重設加入合理的速率限制及輸入驗證；避免重複註冊、名稱大小寫繞過及帳號枚舉。
- 新帳號需正常建立遊戲初始存檔／玩家資料，並沿用現有登入後雲端初始化與裝置帳號限制。
- 嚴禁刪除、重建、合併或更換任何既有 Auth user；嚴禁重設既有玩家密碼；嚴禁修改既有存檔、骰子、寵物、貨幣、成就、任務及歷史紀錄。
- 不修改遊戲經濟、骰子機率、天氣、寵物或其他無關功能。

## 驗收條件

- [ ] 三組指定既有帳號都映射到原 Auth UID；玩家名稱與原 Gmail 均可用原密碼登入同一帳號。
- [ ] 其他未設定登入名稱的舊帳號仍可使用原 Gmail／原密碼登入。
- [ ] 新玩家只需玩家名稱、密碼及確認密碼即可註冊，過程不寄送任何 Email。
- [ ] 重複名稱（含大小寫不同）會被拒絕；註冊失敗不留下孤兒 Auth user 或半套遊戲資料。
- [ ] 登入名稱登入成功後取得正常 Supabase session，切頁／重新整理仍可持續登入。
- [ ] 管理員清單顯示登入名稱、UID、帳號狀態；一般玩家無法呼叫管理員功能。
- [ ] 管理員可設定新密碼並留下稽核紀錄；任何介面與 API 都不能讀取或顯示原密碼。
- [ ] RLS、Edge Function 權限、速率限制、帳號枚舉防護及 service-role key 隔離通過安全檢查。
- [ ] 專項測試、相關存檔／登入回歸測試、語法檢查及 diff 檢查通過。
- [ ] Supabase migration 與 Edge Function 部署成功；GitHub Pages 部署成功；以測試帳號驗證 Gmail 舊登入及新名稱註冊／登入。
- [ ] 驗證期間既有玩家 UID、存檔與遊戲資料未被修改。
