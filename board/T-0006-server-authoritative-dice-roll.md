## 任務

建立雲端模式的伺服器權威擲骰交易。伺服器負責隨機結果、骰子資產、效果消耗及一次擲骰衍生的權威狀態；前端只提交操作意圖並呈現回傳結果。

## 範圍與禁止

- 只動：
  - roll_dice RPC／必要資料結構、伺服器 CSPRNG 與無偏抽樣、骰池／權重規則、骰子入袋與容量、首次發現、統計／最佳紀錄、權威事件、request ID 冪等。
  - 建立天氣、手套、藥水及已核對寵物效果的權威讀取／消耗接點。
  - 在擲骰產物處理套用三項偏好，但偏好不得更改抽樣機率或權威規則。
- 不要動：
  - 完整出售／背包擴充交易（T-0007）、手套管理（T-0008）、藥水庫存生命週期（T-0009）、天氣管理交易（T-0010）、grant 領取（T-0011）、完整寵物系統（T-0012）。
  - 客戶端不得傳入可信骰子結果、機率、稀有度、資產增量、伺服器時間或效果消耗結果。
  - 舊寵物／舊效果未核對前不得提供權威加成；不得靜默丟棄或認列未核對效果。
- 實作前依 Board 規則取得本任務專用 branch／worktree 的人類授權；不得自行建立。

## 驗收條件

- [ ] 雲端擲骰由伺服器抽樣，使用 CSPRNG 與無偏取樣；前端不能指定結果或影響權重。
- [ ] 擲骰結果、背包、首次發現、統計、效果消耗及事件在同一交易提交；失敗全部 rollback。
- [ ] request_id 重試回傳原結果，不重抽、不重複扣效果或增加資產；相同 ID 不同參數必須拒絕。
- [ ] 伺服器依權威狀態讀取有效天氣、手套、藥水及已核對寵物效果，並原子處理一次性消耗。
- [ ] 雲端前端不再呼叫本機 weightedRoll() 產生權威結果，也不自行更新擲骰衍生資產。
- [ ] 補上未授權、跨帳號、重複請求、併發及 rollback 測試；依任務範圍選用適用案例。
- [ ] git diff --check exit 0；相關測試指令與 exit code 記錄於任務紀錄。
