## 任務

實作未登入離線模式的多玩家槽位與本機存檔管理。離線資料只留在本機離線儲存區，不得被雲端登入流程當成可信資產。

## 範圍與禁止

- 只動：
  - 離線槽位建立及選取、IndexedDB 儲存、舊 LocalStorage 資料明確匯入、單槽位匯出／匯入、schema/version、資料驗證、原子替換。
  - 依 Owner 決策支援匯入建立新槽位或覆蓋既有槽位；覆蓋前二次確認。
  - 依 Owner 決策支援刪除前二次確認，並提供先匯出備份或不備份直接刪除。
- 不要動：
  - 雲端登入／bootstrap、雲端權威資料、遊戲權威規則、Supabase schema／RPC／RLS／grants、正式部署。
  - 不得提供離線進度或資產轉成雲端權威資料的捷徑。
- 實作前依 Board 規則取得本任務專用 branch／worktree 的人類授權；不得自行建立。

## 驗收條件

- [ ] 可建立及選取多個離線玩家槽位，槽位資料彼此隔離。
- [ ] 離線存檔有明確 schema/version 與完整性驗證；不合法匯入不覆蓋現有槽位。
- [ ] 匯出僅包含單一指定槽位及該槽位的純個人設定。
- [ ] 匯入、匯出、刪除或 IndexedDB 操作失敗時，不留下半套資料或誤刪其他槽位。
- [ ] 離線存檔操作不呼叫雲端存檔寫入 API；測試多槽位、損毀資料、覆蓋取消及刪除取消。
- [ ] 補上未授權、跨帳號、重複請求、併發及 rollback 測試；依任務範圍選用適用案例。
- [ ] git diff --check exit 0；相關測試指令與 exit code 記錄於任務紀錄。
