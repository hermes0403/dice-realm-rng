## 任務

平行處理鯊皇活動專屬的可信事件接點，讓活動任務能接收伺服器權威交易產生的事件，安全累積進度並冪等發放鯊皇幣。此任務只負責鯊皇活動側的事件契約、接收／映射、進度整合及測試；擲骰、藥水、寵物等核心交易本身仍由各原任務負責。

## 範圍與禁止

- 只動：鯊皇活動專屬 SQL／RPC／trigger／事件映射、活動端前後端整合、相關測試及本任務紀錄。
- 先完成不依賴前置任務的事件契約盤點、映射設計、測試案例與可獨立實作的活動端程式。
- 待 T-0006、T-0009、T-0012 提供可信交易事件後，再接通擲骰、藥水、寵物合成／品質／變異／持有數量等進度。
- 不修改 T-0006、T-0009、T-0012 的任務狀態、內容或程式責任；不得重做其核心交易 RPC。
- 不把客戶端可自行寫入的存檔欄位、合成日誌或藥水日誌當作可信事件來源。
- 不改變鯊皇活動目前僅管理員可見／進入的限制；不公開活動入口。
- 不改動一般遊戲機率、金錢、寵物收益、天氣觸發條件及非活動流程。
- 不部署 GitHub Pages；正式 Supabase 操作依既有授權與驗證規範執行。

## 驗收條件

- [ ] 建立明確的鯊皇活動可信事件契約，列出事件名稱、來源交易、必要欄位、唯一事件 ID 及冪等規則。
- [ ] 活動端只接受由伺服器權威交易產生、可驗證來源的事件；客戶端不得直接提交可領獎進度。
- [ ] 每個事件只更新目前已解鎖任務；完成後原子發獎並解鎖下一項。
- [ ] 重複事件、併發事件、重試及重新登入均不會重複累計或重複發獎。
- [ ] T-0006、T-0009、T-0012 尚未完成時，明確保留相應事件為未接通，不以模擬或客戶端資料冒充驗收。
- [ ] 與既有寵物出售、天氣召喚事件相容，不重複計數。
- [ ] 測試涵蓋偽造事件拒絕、事件去重、任務順序、獎勵冪等及玩家資料隔離。
- [ ] 活動入口與頁面仍只有管理員可見／進入。
- [ ] 記錄實際測試命令、exit code、未完成依賴；不得宣稱未執行的測試通過。
